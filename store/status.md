### Data safety — какво е декларирано

Четири типа, всичките само **Collected**, никога **Shared** (Firebase е
доставчик на услугата от твое име, което изрично е изключение):

| Тип | Къде | Задължително |
|---|---|---|
| Email address | вход/акаунт | по избор (виж бележката за режима без акаунт) |
| User IDs | Firebase `uid` | по избор |
| Other info | текстът на бележките | по избор |
| **Health info** | `cycleData`, месечен цикъл | по избор |

Не се отмята нищо от Messages (Emails / Other in-app messages) — това са
съдържание на чужди писма и чат между потребители, каквито iForget няма.
Веднъж вече бяха отметнати по погрешка и трябваше да се махат.

⚠️ **Режимът без акаунт променя два отговора** (промяната дойде от App
Store Guideline 5.1.1(v), но важи и тук — същият `index.html`):

- **App access** — приложението вече е напълно използваемо без вход,
  значи истинският отговор е "всичко е достъпно без специален достъп".
  Тестовият акаунт може да остане като бележка към ревюиращия, за да
  провери и синхронизацията, но не е задължителен.
- **Data safety → required/optional** — щом акаунтът е по избор, имейлът,
  `uid`-то и бележките се събират само ако човек сам реши да се
  регистрира. Значи **"Users can choose whether this data is collected"**,
  не "required".

### Следващите стъпки

1. **Пресглоби пакета.** Този на диска е от 24.08 и НЯМА режима без
   акаунт:
   ```
   cd ~/iforget && git pull origin main && npm run sync
   cd android && ./gradlew bundleRelease
   ```
   Проверка, че новото наистина е ВЪТРЕ в пакета (връща число > 0):
   ```
   unzip -p app/build/outputs/bundle/release/app-release.aab \
     base/assets/public/index.html | grep -c guestMode
   ```
   `versionCode` е още **1**. Ако версия 1 вече е качена в кой да е трак,
   вдигни го в `android/app/build.gradle` — Play отказва повторно качване
   със същия номер.
2. Closed testing → Alpha → **Select testers** (email list) → **Create a
   new release** → качваш `.aab` → Save → Send for review.
3. Разпращаш opt-in линка. Тестерите трябва да са **Google акаунти** и да
   останат записани през целите 14 дни — покани 15 души за резерв.
4. След 14-те дни: **Apply for production** (има и въпросник за самия
   тест) → чак тогава публично пускане.

Това е реален капан от миналото: `npm run sync` копира ЛОКАЛНИЯ файл, а
`git pull` беше пропуснат — build-ът минава, приложението работи, само
поправката липсва.

Пуска се ръчно от Actions → "iOS release (TestFlight)" → Run workflow.

### Двата кръга ревю — какво поискаха и защо

**1. Guideline 2.1 — Information Needed.** НЕ отказ заради бъг: Apple иска
видеозапис от реално устройство плюс писмени отговори на 7 въпроса, преди
изобщо да започне ревюто. Рутинно за нов акаунт. Готовият текст и целият
контекст са в `store/app-review-notes.md` (⚠️ полето приема най-много 4000
знака; видеото се дава като линк — YouTube **Unlisted**, не Private).

**2. Guideline 5.1.1(v) — не може да се иска регистрация за функции, които
не зависят от акаунт.** Това беше истинска, основателна промяна: при
iForget писането на бележки винаги е било локално (`save()` пише в
localStorage синхронно, Firestore записът е под `if(currentUser)`) —
липсваше само врата към това състояние. Оттам режимът без акаунт: бутон
"Продължи без акаунт", `guestMode` в localStorage и `mergeGuestNotes()`,
което слива локалните с облачните при по-късен вход, за да не се губят.

⚠️ **Помни го при всяка бъдеща функция:** ако нещо ново работи и без
акаунт, не бива да се заключва зад вход. Същото правило важи и занапред.
